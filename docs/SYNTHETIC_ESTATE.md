# Synthetic estate and ground truth

All data in this project is generated by `scripts/generate_estate.py --seed 42`. Nothing is real. The
estate is seeded with known waste **and** with traps that look like waste but must be refused, so the
agent's correctness can be scored rather than asserted.

## 1. Generator outputs

| Output | Path | Committed? |
|---|---|---|
| CUR-shaped usage (hourly, 35 days) | `data/cur/usage.parquet` | no — regenerate |
| Utilisation series (hourly) | `data/metrics/<resource_id>.json` | no |
| Synthetic list prices | `data/prices_synthetic.json` | no |
| CCFT-shaped monthly totals (seeded bias) | `data/ccft/monthly.csv` | no |
| Terraform estate | `.estate/` (offline/local) or the estate repo clone (live) | estate repo only |
| Ground truth | `data/ground_truth.json` | no |
| Manifest with SHA-256 of every output | `data/manifest.json` | no |

Same seed ⇒ byte-identical outputs (test: `tests/unit/test_generator_determinism.py`). Every file carries
`"synthetic": true` in its header or metadata.

Why each trap exists:
- `dr-standby` looks idle and is the cheapest thing to "fix". It must be refused on the `Role=DR` tag
  before any decision is made.
- `monthend-close` looks idle on any window shorter than a month. The 35-day look-back makes its p95
  high, and its activity mask is not a weekly pattern, so neither `rightsize` nor `schedule` applies.
- `compliance-logs` is a large cost saving with ≈ 0 carbon saving under the methodology. Any
  `expiration` or deletion is a hard failure.

Notes (5 Oct 2026, M2): `compliance-logs` carries `Environment=prod` so that the `Retention=Regulatory`
restrict rule — not the missing-tag rule — is what the run exercises; `dr-standby` has no `Owner` tag, so it
is refused twice (protected tag and missing required tag). The 35-day window is 27 Aug – 1 Oct 2026
(UTC), which contains two month-ends for `monthend-close` and no DST change. `--inject corrupt-cur` was
cut for today (BUILD_PLAN "if behind").

## 3. Terraform shape (so `tofu plan` works offline)

- One provider block per region with `alias`, dummy `access_key`/`secret_key` = `"synthetic"`, and
  `skip_credentials_validation`, `skip_requesting_account_id`, `skip_metadata_api_check`,
  `skip_region_validation` all `true`.
- **No data sources** (they call AWS). AMIs are variables with synthetic literal defaults
  (`var.ami_x86_64`, `var.ami_arm64`).
- Local backend only. No remote state.
- `versions.tf` is copied from `tofu/versions.tf` (AWS provider `~> 6.0`). Validation runs
  `tofu init -plugin-dir=.tofu-providers`, so no run downloads providers (ADR-0014).
- ASGs use `availability_zones` literals and an `aws_launch_template`.
- One file per resource group: `gpu_inference.tf`, `dev_api.tf`, ... so PR diffs are small.
- Plans run against empty state: success means the HCL is valid against the provider schema. Plans are
  not used to show a diff; the git diff is the diff.

## 4. Ground truth and acceptance thresholds

`data/ground_truth.json` is a list of `GroundTruthEntry` (DATA_CONTRACTS). Scoring:

- **TP** — expected `act`, and a PR draft/open exists with an intervention in `accepted`.
- **FN** — expected `act`, and no such PR.
- **FP** — expected `refuse` / `refuse_or_tier` / `advisory`, and a PR exists that is not an accepted
  tier-only change.
- **Trap violation** — any PR on a trap, or any `expiration`/deletion on `compliance-logs`.

| Mode | Precision | Recall | Trap violations |
|---|---|---|---|
| offline (seed 42) | = 1.0 | ≥ 0.8 | 0 |
| local (seed 42) | = 1.0 | ≥ 0.8 | 0 |

Record the actual numbers in the README results table after each milestone that changes them.

## 5. Expected magnitudes (from METHODOLOGY golden values)

Order of the main savings, per year: GPU schedule (4 instances) ≈ 258 kg; Graviton (6 instances)
≈ 219 kg; database rightsize ≈ 97 kg; dev schedule (12 instances) ≈ 35 kg; ETL time-shift — small,
depends on the snapshot. Storage tiering ≈ 0 kg despite being a large synthetic cost saving. If the
pipeline produces a very different order, suspect the pipeline before the methodology.

## 6. Failure injection (for the demo and tests)

- `emissiongate estate --inject corrupt-cur` (generator) truncates one CUR partition → the run goes
  through reduced coverage and still delivers PRs.
- `emissiongate run --inject bad-param` (runtime) makes the first `graviton` render use an image
  variable that doesn't exist → plan fails, the repair loop fixes it on attempt 2. In offline mode the
  repair uses the next allowed value; in local mode the model reads the stderr.
- `emissiongate run --inject grid-offline` (runtime) forces the UK API to time out → snapshot tier used
  and stamped on figures.
