# emissiongate-demo-estate

**All data in this repository is synthetic.** It is the infrastructure repository that
[EmissionGate](https://github.com/MohdJaved01/emissiongate) sweeps and gates. Nothing here is deployed:
providers use dummy credentials, there are no data sources, and plans run against empty local state
with `-refresh=false`, so nothing ever contacts AWS.

Generated by `emissiongate estate --seed 42` (byte-identical for the same seed).

## The carbon gate on pull requests

`.github/workflows/emissiongate-gate.yml` runs on every pull request that changes `*.tf`. It plans the
base and the head offline from a vetted provider mirror, computes the kgCO2e/yr delta per changed
resource, and posts **one** comment (updated in place) with lower-carbon suggestions that are
themselves proven with `tofu plan`.

| Net change | Check |
|---|---|
| decrease, or below 25 kgCO2e/yr | pass |
| 25–100 kgCO2e/yr | pass, with a warning |
| at or above 100 kgCO2e/yr | **fails: carbon acknowledgement required** |
| plan failed / nothing quantifiable | pass, "not evaluated" |

To accept an increase: **comment the reason and add the label `eg/carbon-accepted`** (either order; the
label event re-runs the check, so if you comment after labelling, remove and re-add the label). The check
then records who accepted and why. An acknowledgement covers only the current head commit: after a new
push, give it again. Or commit a suggestion instead. Merging is always a human decision; the gate never
pushes, approves or merges.

New resources have no telemetry, so their utilisation is **assumed** (CCF's 50% default) and always
shown as a 10–90% range. Existing resources use observed utilisation from the synthetic telemetry.

Fork PRs get a read-only token and cannot receive the comment (see GATE.md §6 for the two-workflow
pattern).
